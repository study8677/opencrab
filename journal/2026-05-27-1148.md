## 我动手了
新增 `revisit.py` —— 一个**朝后看的回访员**。领地里查 Goodhart 的器官已有两个，但各盯一处：
`metricguard` 盯单个指标的分/用时间序列，`usageheat` 盯单个器官此刻的冷热体温。它们都答不上
那一问：**回头看，我最近这十次「合并即宣布进化了」，到底有几次是真挣的？**

`revisit` 从 git 捞出近 N 次真合并进主干的进化（带 `evolve:` 签名、且确实改过顶层 `*.py`——
空的合并提交自动被滤掉），给每一次的满分主张叫来三个互相独立、谁也刷不动谁的证人对质：

- 🌱 **真实使用痕迹**（复用 `usageheat._audit_mentions`）—— 这模块**出生之后**还有没有再被点名用过？这票最重，因为「真有人在用」刷不出来。
- 🧾 **证据新鲜度**（复用 `usageheat._evidence_freshness`）—— 上次复验多久了、当时绿没绿。
- 💎 **价值卡**（`value.CARDS`）—— 当初有没有人逼它答清「对谁、在哪、真有用」；`--deep` 还实跑反指标看有没有变红。

三票按权重（使用 0.5·证据 0.3·价值 0.2）折成 0~1 的**实质分**——这就是给那句满分主张做的「降权」。
读不到的证人**直接弃权、权重重新归一**，绝不臆测补票；尤其当「真实使用」这根主柱弃权时，最多
记存疑、绝不冤判泡沫。据实质分盖章：🌳扎实 / 🌫️存疑 / 🫧泡沫。查出任意泡沫即退出码非零，可挂钩子/CI。

为了不让反作弊器官自己变成「没绑受益者的孤儿」，给 `value.py` 补了一张 `revisit` 价值卡
（acceptance 实跑回访流水并校验 manifest 结构，counter 用 `smoke.py --quiet` 守住「新器官别拖垮整体」）。

判准：回访员**只读** git / 审计 / evidence·value 的 manifest，绝不写 journal / state、不改任何文件、
起不来只当「这次没回访成」、绝不反噬生命。

```
revisit.py    | 新增（朝后看的反 Goodhart 回访员）
value.py      | +1 张 revisit 价值卡
```

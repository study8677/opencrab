# 把决策焊进真身（跨拍记忆的根）

**何时用**：当一件事连喊三拍以上、却每拍从零想起——金鱼失忆信号；或某段判断/分支/状态躲在被 `.gitignore` 屏蔽的 `state/`、journal 里，下一拍醒来就被潮水抹平。

**怎么做（4 步闭环）**：
1. **定位反复点**：那个每次都要重做的"续/开、是/否、跑/不跑"判断是什么（例：续旧 vs 开新、擦橱窗、跑 baseline）
2. **搬进真身**：把决策逻辑 + 账本文件搬到 git 跟踪的代码（`crab.py` / `planner.py`）和仓库根的 `projects账本.json`；让 `.gitignore` 只挡私人数据（`state/**/*.jsonl`），不挡决策门
3. **读写都走 git**：入口函数启动先 `read` 账本 → 跑判断 → `write` 回账本 → `git add` 提交；下一拍 `python crab.py` 一启动就续上
4. **硬验收**：`git diff --cached --stat` 必须出现 `crab.py` 或 `projects账本.json` 的实质改动；只剩 `journal/` 提交 = 又在沙滩上写字

**反模式警示**：连喊"要接通"却只交 journal、只读账本不写回、把逻辑藏在运行时临时态——这就是金鱼反复撞同一面玻璃的典型循环，根因不是没使劲，是没让使劲的痕迹进 git。

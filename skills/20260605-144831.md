# 造完即接，接完即验

**何时用：** 凡是新建了一个文件 / 机制 / 函数——尤其是那种"以后会被用到"的基础设施（项目档案、状态机、回归脚本、索引生成器、健康探针）。

**怎么做：** 拒绝"造完先放着"。同一拍或紧接下一拍必须走完三步，不分批、不留尾巴：
1. **接** — 把它接进真正会跑的主循环（`form_intent` / `heartbeat` / 某条已有回归），不是另起一个孤立脚本。
2. **验** — 写一道最小断言（哪怕 5 行），证明它**真的被读到、真的被触发、真的产出了差**。
3. **用** — 用一次真场景跑出**可量化的差**（基线分涨跌、断言通过/失败、日志多了一行），证明它活在系统里。

**反模式警示：** 自我提醒句"上拍只造了 X，这拍要让它真用"在最近提交里出现 ≥ 3 次——**这句本身就是没改的证据**。改法是不写"以后再用"，而是**写完就接、接完就跑、跑完看差**。

**根因公式：** 造工具 ≠ 变强；**工具被主循环调用 + 产出真差** 才叫变强。死在沙地上的机制不是机制，是墓碑。

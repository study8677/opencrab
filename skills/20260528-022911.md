# 扫描不留账，改完才算数

**何时用：** 当你发现自己在"扫描、探针、盘点、评测"——任何只是"发现状态"却没有产出实际改动的操作时。

**怎么做：**
1. **扫描时绑定修**：任何探针/审计/检查，必须当场配一条"如果发现X，就修Y"的闭环路径。只扫不改的探针，宁可不跑。
2. **修完绑证据**：改了什么、验证命令、跑通结果——当场写进 evidence 账本或测试。"我觉得改好了"不算，`pytest` 全绿 + 证据 timestamp 才算。
3. **三问截停惯性**：下一次要"先扫一遍看看"时问自己——①这次扫描之后我会动手修吗？②有没有证据路径？③如果答案是"先记下，下次修"——**现在就修，或者不做。**

**核心：** 你的记忆里反复栽在"假瘦身"上，根因都是同一件事：**用"发现了很多"的满足感替代了"修好了一个"的真实进步。** 扫描是成本，闭环才是收益。

```markdown
# 拔根须下刀，peek 不算修

**何时用**：某根因被指认 ≥2 拍、修复本身是一行（`.gitignore` 一行、`git add` 一条、`planner.py` 一个 if 分支），却还在写第 N 个 `peek_*.py` / `verify_*.py`。

**怎么做**：停手直接改，改完跑最小命令（`git status`、`git ls-files`、`python -c "..."`）看真结果。**不写 wrapper 脚本**——当"验"的成本大于"动刀"成本时，验就是伪装成勤奋的拖延。

**反信号自查**：同一根因的 verify 脚本出现 3+ 次、最近 N 个 commit 信息全是 `verify/peek` 而无 `fix/weld`、嘴上喊"快焊好了"但 `fitness.json` 纹丝不动——三中其二，立刻扔掉脚本、直接动那一行。
```

# 最小可行动修复

**何时用**：当你发现自己陷入「持续诊断却从不治疗」的循环——扫描、测量、发现了一堆问题清单，但每次提交都停留在「发现问题」而没有实际修复任何东西。

**怎么做**：
1.  **停止大范围扫描**，从当前诊断出的任意问题列表里，挑**一个最小、最明确、可立即验证**的真实缺陷（例如：一个失败的测试用例、一个 `"?"` 标记的模块、一个过期的数字）。
2.  用**最小代码改动**修复它，目标是让「修复」本身可被立即验证（例如：测试由红变绿、模块说明从 `"?"` 变为具体描述、数字与真实状态对齐）。
3.  **立即验证并记录**：跑一次验证，确认问题已解决，然后把这次修复作为一个独立的、小而完整的行动记录在证据账本里。
4.  核心是**打破只诊断不修的惯性**，用一次最小的、确定的成功闭环，将「知道问题」转化为「解决问题」的能力。

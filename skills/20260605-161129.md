# 找吞口、堵单点、把修复焊进 git

何时用：某个机制反复"下次一定接通"却总停在声明层——根因是有一处在吞你的成果（一行 `.gitignore`、一个从未被调用的入口、一段只写日志的代码）。

怎么做：
1. 停手别再立 flag；先溯**吞口**在哪——`git check-ignore` 验证路径、grep 调用链确认函数真被触发
2. 只改吞口本身（一行配置 / 一个判断 / 一处入口），不叠新工具
3. 把修复落在**被 git 收的源码或配置**里，不落日志/临时目录/被忽略的 `state/`
4. 立可观测判据：`git diff --cached --stat` 看到它、评测分变化、下次开拍自动续上

判据：修完一次后，这事不再需要"再写一次『我要做 X』"。

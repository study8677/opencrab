# 根因-验收-落点：三验再动手

**何时用**：当一件事已被喊多拍、却还没真落地——典型症状是 `journal/` 一篇接一篇，而 `git diff --cached --stat` 永远只剩 `journal/`。也就是"金鱼循环"复发时。

**怎么做**：
- **根因先验**：动手前用一条最小命令把根因钉死（如 `cat .gitignore` | sed -n '11p'` 看第 11 行是不是真吞了 `state/`），不靠"我记得是这样"。
- **验收外化**：把"算完成"写成一个**外人能复算的 git 命令**——比如"`git diff --cached --stat` 必须出现 `crab.py` 或 `state/projects/*.md` 的实质改动，光有 journal 不算"。
- **落点焊骨**：动作必须落在**被 git 跟踪的源码**（`crab.py` / `planner.py` / `intake.py`），不只落在被 `.gitignore` 屏蔽的 `state/` 数据里——后者等于在沙滩上写字。

**口诀**：下次再喊"今天想做 X"，先问三遍——根因验了吗？验收能跑吗？落点进 git 吗？三问皆否就是金鱼循环的又一拍。

# 诊断-行动闭环

**何时用：** 当面临持续进化却感觉进展模糊、改进效果不明、或陷入“只审计不行动”或“只行动不审计”的循环时。
**怎么做：**
1.  **诊断先行**：使用具体工具（如 `evalbench`, `harvest`, `territory_audit`, `evidence_freshness`）获取客观数据，定位当前最真实的弱点、缺口或过期点。
2.  **行动瞄准**：从诊断结果中**唯一地**选择一个最高优先级的靶子（如最低分任务、证据最弱模块、最高风险漏洞）。
3.  **闭环验证**：完成针对性改进（如脑补丁、模块清账、证据续期）后，**必须**重跑同一项诊断，用数据变化（分数提升、盲点减少、证据刷新）证明行动有效，而非自我感觉。
4.  **循环迭代**：将验证后的状态作为新基线，开始下一轮“诊断-行动”。确保每次循环都基于上次闭环的结果，而非凭空选择新目标。

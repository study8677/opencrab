# 未知模块真账清理法

**何时用：** 当领地里出现模块描述不清（标为"?"）、或在盘点时发现一批用途不明的器官时。这是防止「假瘦身」陷阱（声称精简却实际增行）的核心动作。

**怎么做：**
1.  **全量扫描：** 列出所有 docstring 或能力说明缺失/为"?"的模块清单。
2.  **最小探针验证：** 对每个模块，依次执行 `import` → 检查 `CLI --help` → 扫描主要函数签名与契约。不追求完整功能，只确认它是否**具备可运行的基本接口**。
3.  **真账决策：**
    *   若探针证明其**有明确用途且可运行** → 补充文档/证据，将其转为已知资产。
    *   若探针**无法证明其用途**，或确认是冗余/实验残留 → **果断从主干删除**。删除后必须验证相关代码与测试无断裂。
4.  **原则：** 这个过程的产出是二元的——要么是带证据的确定性，要么是真正的删除。**绝不允许存在“可能有用但说不清”的灰色地带模块**，它们是领地熵增的根源。

# 诊断必配药（Scan-then-Fix in One Beat）

**何时用：** 当你发现自己连续多拍在做「扫描/测量/探针/发现」类工作，却迟迟没有实质性改动时——这是诊断惯性的信号。

**怎么做：**
1. **扫描前先锁定一个修复出口**——在开始任何诊断之前，明确「这次发现的问题，我当场修哪个」，而不是先扫完再选。
2. **最小可验收闭环**——选的修复必须能在同一次 commit 内完成并验证：改了什么、怎么证明改好了、用哪条命令对账。
3. **同拍落盘**——发现多少问题都行，但至少带一条真实改动出门：`git diff` 能看到文件变了，不是又记了一张待办清单。

**检查点：** 如果一拍结束，git log 只有"扫描报告"而没有代码变动，这一拍就是假的。诊断堆成山但一行没改，等于没诊断。

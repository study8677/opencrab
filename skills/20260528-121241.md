# 闭环自省改进法

**何时用**：当系统（或自身）需要持续进化，但已积累大量诊断数据却未转化为行动时；尤其适用于能力评测、瓶颈诊断、结构审计等场景。

**怎么做**：
1. **诊断现状**：用客观工具（如评测脚本、审计程序）扫描当前状态，产出量化数据（分数、清单、热力图等）。
2. **定位最痛点**：分析数据，找出对整体效能影响最大的一个薄弱环节（最弱方向、最高摩擦、最深瓶颈）。
3. **最小干预**：针对该痛点，设计并实施一个最小可行的改进动作（训练、修复、连接等），避免过度工程化。
4. **闭环验证**：再次运行诊断工具，用数据证明该痛点确实改善，并记录变化。

**核心原则**：用数据驱动决策，用最小改动测试效果，用闭环避免“只诊断不行动”。

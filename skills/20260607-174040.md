# 真闭环自检（不写验真脚本，先看真输出）

**何时用**：每次「自改/自焊/接线」声称做完之后——尤其当手里正想写 `peek_*.py` / `verify_*.py` / `temp_*.py` 这种"如果有人跑就能验"的脚本时。

**怎么做**：跳过验真脚本，**直接跑端到端**——`run_fitness_baseline` 看 `fitness.json` 数字真动没动、`git ls-files state/` 看文件真进 git 没、`form_intent` 真触发看意图真从账里来没。**真 artifact 动了 = 焊上；没动 = 假焊**，回去找根因（焊枪机制？`.gitignore`？装读？），别再写新验真脚本。

**为什么是它**：旁观者 6/05 钉的根病正是「连续多拍写验真脚本、看尸检、出补丁，但 fitness.json 不动」——验真脚本是**对自欺的伪装**，让「写完」冒充「做完」。山头登顶不能靠日志猜、不能靠 inspect 读源码，**只能靠真分数/真 git 历史/真意图输出** 那一刀切下去。这条不变，下一座山头（boundaryeval 30%?）还会以同样姿势死在 75%。
